Lección 2: Instrucciones de Movimiento y Aritmética

En la arquitectura Aarch64, las instrucciones siguen un formato estándar. Por regla general, el primer registro que escribes es el destino (donde se guarda el resultado) y los siguientes son los orígenes (los datos que se van a operar).

1. Regla de Oro: La Sintaxis de Operandos

La estructura de casi todas las instrucciones en ARM de 64 bits es la siguiente:

INSTRUCCION destino, origen1, origen2

Aclaración Importante: ¿Qué significan Xd, Xn y Xm?

Cuando revises manuales de programación o guías de Aarch64, verás que las instrucciones usan letras minúsculas como Xd, Xn o Xm. Estas letras no se escriben tal cual en el código; son marcadores de posición que representan lo siguiente:

  • Xd (Destino): La letra d viene de Destination. Es el registro donde el procesador guardará el resultado final de la operación. Siempre se escribe en la primera posición.
  • Xn (Primer Origen): La letra n representa al primer registro que aporta datos para la operación. Se coloca en la segunda posición.
  • Xm (Segundo Origen): La letra m representa al segundo registro que se va a operar (sumar, restar, etc.). Se coloca en la tercera posición.

Ejemplo real: Si la teoría te dice ADD Xd, Xn, Xm, tu código real reemplazando los marcadores por registros válidos se verá así: ADD X11, X9, X10.

2. Las 3 Instrucciones Fundamentales

Para manipular los registros que aprendiste en la lección anterior, necesitas dominar estos tres comandos:

  1. MOV (Move): Copia un valor dentro de un registro. Puede copiar un número directo (llamado valor inmediato) o duplicar el contenido de un registro en otro.
    Sintaxis: MOV Xd, Xm o MOV Xd, #inmediato
  2. ADD (Add): Suma dos valores y guarda el resultado en el registro destino. Puede sumar dos registros, o un registro y un número directo.
    Sintaxis: ADD Xd, Xn, Xm o ADD Xd, Xn, #inmediato
  3. SUB (Subtract): Resta el segundo operando del primero y almacena el resultado en el registro destino.
    Sintaxis: SUB Xd, Xn, Xm o SUB Xd, Xn, #inmediato

3. Guía de Restricciones Técnicas Importantes

Aarch64 es muy estricto con sus operaciones. Tus alumnos deben conocer estas reglas para no generar errores de compilación:

  • Consistencia de tamaño: No puedes mezclar registros de diferentes tamaños en la misma instrucción. Ejemplo: ADD X0, X1, W2 es un error. Deben ser todos X (64 bits) o todos W (32 bits).
  • El prefijo de los números (#): En Aarch64, cada vez que uses un número directo en el código, debes poner obligatoriamente el símbolo de numeral antes. Ejemplo: #5 o #0x20 (para hexadecimal).
  • Límite de los números inmediatos: Con MOV, ADD y SUB, el número directo máximo que puedes usar directamente es de 12 bits (un valor entre 0 y 4095). Para números más grandes se usan técnicas avanzadas.

4. Ejemplo Práctico Estructurado

Analiza el siguiente bloque de código donde aplicamos los registros de trabajo temporales junto con las nuevas instrucciones:


// 1. Inicializamos los registros con valores iniciales
MOV X9, #25          ; Copia el número 25 en el registro temporal X9
MOV X10, #10         ; Copia el número 10 en el registro temporal X10

// 2. Realizamos operaciones matemáticas
ADD X11, X9, X10     ; Suma X9 + X10 (25 + 10). El resultado (35) se guarda en X11
SUB X12, X11, #5      ; Resta 5 a X11 (35 - 5). El resultado (30) se guarda en X12

// Al finalizar, X12 contiene el valor 30 de forma segura
