Lección 5: Anatomía del Código y Hola Mundo

Un programa ejecutable en Aarch64 no es solo una lista suelta de instrucciones. El código se divide estrictamente en secciones (sections) y directivas que organizan la memoria RAM.

1. Las 3 Secciones Obligatorias del Sistema

Cuando el Kernel del sistema operativo carga tu programa, busca estas tres etiquetas para saber qué hacer:

  • .data (Sección de Datos Inicializados): Aquí se reservan y guardan las variables fijas que ya tienen un valor desde el principio. Por ejemplo, cadenas de texto, mensajes de error o constantes numéricas fijas. Ocupa espacio real en el archivo ejecutable final.
  • .bss (Block Started by Symbol): Sección reservada para variables globales que **no** tienen un valor inicial (empiezan en cero). Sirve para reservar grandes bloques de memoria RAM estática (buffers) donde guardarás datos que el usuario introduzca más adelante. No ocupa espacio en el disco duro.
  • .text (Sección de Código): Esta es la sección sagrada. Aquí es donde se escriben las instrucciones reales del procesador (como MOV, ADD, SVC). Esta memoria se marca como "Solo Lectura" para evitar que el programa se modifique a sí mismo por accidente.

2. Directivas de Enlazado de Red

Para que el compilador y el sistema operativo se comuniquen, usamos instrucciones especiales llamadas directivas (llevan un punto al inicio):

  • .global _start: Le avisa al enlazador (Linker) que la etiqueta _start debe ser visible desde fuera del archivo. Es obligatoria para que el sistema operativo sepa en qué byte exacto arranca la primera línea de tu programa.
  • _start:: Es el punto de entrada oficial (Entry Point). Todo lo que esté arriba de esta etiqueta no se ejecutará al inicio.

3. Código Fuente Completo: Tu Primer Hola Mundo

Analiza el esqueleto de un programa real listo para compilar en Linux Aarch64. Usaremos la llamada al sistema 64 (sys_write) para imprimir y la 93 (sys_exit) para salir de forma limpia:


.data
    msg:    .ascii "¡Hola Mundo desde Aarch64!\n"  ; Nuestro texto en memoria
    len = . - msg                               ; Calcula el tamaño del texto

.text
.global _start

_start:
    ; ---- PASO 1: CONFIGURAR LA IMPRESIÓN ----
    MOV X0, #1          ; Descriptor: 1 = Pantalla (stdout)
    LDR X1, =msg        ; Cargamos la dirección de memoria de nuestro texto
    MOV X2, len         ; Pasamos la longitud exacta calculada en bytes
    MOV X8, #64         ; Número de Syscall en ARM64: 64 = sys_write
    SVC #0              ; Supervisor Call: Despierta al Kernel para que imprima

    ; ---- PASO 2: SALIDA LIMPIA DEL SISTEMA ----
    MOV X0, #0          ; Código de salida: 0 = Éxito sin fallos
    MOV X8, #93         ; Número de Syscall en ARM64: 93 = sys_exit
    SVC #0              ; Devuelve el control al sistema operativo de forma segura

4. Nota Técnica para los Alumnos

¡CUIDADO! Si vienes de aprender arquitectura Intel x86-64, recordarás que la syscall de salida era la número 60 y la de escritura la número 1. En Aarch64 (ARM de 64 bits), los números del Kernel cambian por completo: la escritura es 64 y la salida es 93. Además, la interrupción ya no se ejecuta con syscall, sino con la instrucción SVC #0.
